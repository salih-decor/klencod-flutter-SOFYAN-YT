# SOFYAN YT — تطبيق Android (Flutter) + خادم FastAPI

تحويل مشروع «SOFYAN YT MVP» (React + Vite + FastAPI) إلى تطبيق Flutter حقيقي لنظام Android،
مع إبقاء FastAPI **خادمًا مستقلًا عبر HTTPS** (لا يعمل داخل APK، ومفاتيح API عليه فقط).

## ⚠️ حالة التحقق (اقرأها أولًا)

| ما | الحالة |
|---|---|
| منطق الخادم الأساسي (RAG، المصادقة، ترحيل قاعدة MVP القديمة، OCR إنجليزي) | ✅ **اختُبر** — 14 اختبار وحدة ناجح (`backend/tests`) |
| مسارات FastAPI (`backend/main.py`) | ⚠️ مُترجمة نحويًا فقط؛ **لم تُشغَّل** (لا FastAPI في بيئة الإعداد). يفحصها `check-backend.yml` |
| كود Flutter/Dart | ⚠️ **لم يُترجَم ولم يُحلَّل**: لم يتوفر Flutter SDK ولا إنترنت. فُحصت الأقواس/السلاسل/الاستيرادات فقط |
| `flutter pub get` / `analyze` / `build apk` | ❌ **لم تُنفَّذ**. لا يوجد APK جاهز، ولا أدّعي نجاح البناء |
| التشغيل على جهاز Android | ❌ لم يُجرَّب (الكاميرا، PDF، الواجهة) |

أول بناء على GitHub Actions قد يُظهر أخطاء ترجمة صغيرة لم أستطع رؤيتها؛ أرسل لي سجل الخطأ وأصلحه.

## بنية المشروع

```
pubspec.yaml · analysis_options.yaml      ← جذر مشروع Flutter (للاستيراد في KlencodIDE: Flutter)
lib/            main.dart + core/ (API, الحالة, النماذج, PDF) + ui/ + screens/
android/        Gradle (AGP 8.7 / Gradle 8.9 / Kotlin 1.9.24 / Java 17)، الأذونات، الأيقونات
assets/logo.png شعار التطبيق
test/           اختبارات Dart (تُشغَّل عبر flutter test)
backend/        خادم FastAPI + Dockerfile + docker-compose (HTTPS عبر Caddy) + tests

.github/workflows/    build-apk.yml · check-backend.yml
```

| 12 | حسابات وقاعدة بيانات | ✅ تسجيل/دخول (PBKDF2 + JWT، حد محاولات) + SQLite | لا استعادة كلمة مرور ولا تأكيد بريد. SQLite تكفي لخادم واحد |
| 13 | RAG في المراجع الجزائرية | ✅ فهرسة مقاطع + استرجاع **BM25 بالكلمات** (تطبيع عربي وتجذيع خفيف) | ليس بحثًا دلاليًا (لا embeddings). يعمل فقط على ما ترفعه |

| 15 | واجهة عربية RTL، ليلي/نهاري | ✅ ألوان وهوية الأصل (#0b1230→#1a1450، بنفسجي) | لم تُرَ على جهاز |

### ما تغيّر عن المشروع الأصلي (بوضوح)
- **الواجهة**: React → Flutter. الشعار في الأصل نص فقط «SOFYAN **YT**»؛ أبقيته نصًا واستحدثتُ أيقونة «SY» للتطبيق.
- **تصدير PDF**: كان «طباعة المتصفح»؛ صار معاينة طباعة/مشاركة PDF من Android (نفس الفكرة).
- **الخادم**: كل المسارات صارت تتطلب تسجيل دخول، والسجل صار لكل مستخدم. **سجلات قاعدة MVP القديمة** تبقى في الجدول لكن بلا مالك فلا تظهر لأحد.
- **OCR**: أُضيف دعم PDF (كان مرفوضًا في الأصل).
- **حُذف**: `check-web.yml` (فحص واجهة Vite) لأن الواجهة لم تعد React؛ حلّ محله `build-apk.yml` و`check-backend.yml`.
- لا ميزة أصلية أخرى حُذفت.

### الأذونات
`INTERNET` فقط. **لم أُعلن `CAMERA` ولا أذونات التخزين عمدًا**: التصوير يتم عبر تطبيق كاميرا النظام، والملفات عبر منتقي النظام (SAF)؛
وإعلان `CAMERA` دون طلبه وقت التشغيل يُسقط التصوير على بعض الأجهزة. نسخة release تمنع `http` (cleartext)؛ نسخة debug تسمح بخادم محلي فقط.

## تشغيل الخادم

```bash
cd backend
cp .env.example .env        # ضع ANTHROPIC_API_KEY و SOFYAN_JWT_SECRET و ADMIN_EMAILS
# محليًا (ويندوز/لينكس): Python 3.12 + Tesseract (ara, fra, eng)
python -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt
uvicorn main:app --port 8000
# إنتاجيًا مع HTTPS تلقائي (نطاق يشير للخادم، المنفذان 80/443 مفتوحان):
docker compose up -d --build
```
اختبار: `python -m unittest discover -s tests -v`

## بناء التطبيق

**محليًا** (Flutter 3.27.4 + Java 17 + Android SDK):
```bash
flutter pub get
flutter analyze --no-fatal-infos
flutter build apk --release --dart-define=API_BASE_URL=https://api.example.com
# الناتج: build/app/outputs/flutter-apk/app-release.apk
```
عنوان الخادم يمكن أيضًا إدخاله داخل التطبيق (شاشة الدخول ← «عنوان الخادم»)، ويجب أن يكون HTTPS.

**GitHub Actions**: ارفع المشروع إلى مستودع؛ `build-apk.yml` ينفّذ `flutter pub get` ثم `flutter analyze --no-fatal-infos`
ثم `flutter build apk --release` ويرفع الناتج في **Artifacts** باسم `SOFYAN-YT-release-apk`.
- لضبط عنوان الخادم: Settings ← Variables ← `API_BASE_URL` (أو الحقل عند التشغيل اليدوي).
- توقيع الإصدار (اختياري): أسرار `ANDROID_KEYSTORE_BASE64` و`ANDROID_KEYSTORE_PASSWORD` و`ANDROID_KEY_ALIAS` و`ANDROID_KEY_PASSWORD`.
  بدونها يُوقَّع APK بمفتاح debug: يُثبَّت مباشرة لكنه لا يصلح للنشر على Google Play.
- `--no-fatal-infos`: لأنني لم أستطع تشغيل المحلّل؛ الأخطاء والتحذيرات تُفشل البناء، والملاحظات الأسلوبية لا.

**KlencodIDE**: استورد المجلد الرئيسي (حيث `pubspec.yaml`) باختيار Flutter. مولّد wrapper الخاص بـ Gradle
وملف `android/local.properties` يُنشئهما Flutter تلقائيًا عند `flutter pub get`/البناء، لذلك لم أضمّنهما.
تأكد أن إصدار Flutter في الـ IDE قريب من 3.27 (يلزم Dart ≥ 3.5).

## أمان وتشغيل — نقاط يجب الانتباه لها
- لا مفاتيح داخل التطبيق إطلاقًا؛ الرمز يُخزَّن عبر `flutter_secure_storage`.
- `SOFYAN_JWT_SECRET`: بدونه يُولَّد سرّ مؤقت وتنتهي الجلسات عند كل إعادة تشغيل.
- التسجيل مفتوح افتراضيًا؛ أغلقه بـ `ALLOW_REGISTRATION=false` بعد إنشاء حسابات التلاميذ.
- لا يوجد تحديد معدّل لطلبات الذكاء الاصطناعي: كل مستخدم مسجَّل يستهلك رصيد مفتاحك. أضف حدًّا قبل فتح التسجيل للعامة.
- المحتوى المولَّد بالذكاء الاصطناعي قد يخطئ؛ التطبيق يقول ذلك ويوفّر «إعادة التحقق»، لكنه لا يغني عن الأستاذ.
